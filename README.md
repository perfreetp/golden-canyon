# 铁路车站信号联锁进路表编制与仿真校验系统

面向设计院**信号设计员、主管审核员、仿真测试员**三类岗位的一体化联锁进路表工具，基于 **Vue 3 + TypeScript + Canvas 2D + Vite** 实现，纯前端运行、本机浏览器持久化，无需后端。

## 功能与角色

| 模块 | 功能 | 主要使用角色 |
| --- | --- | --- |
| 车站管理 | 多车站建档、示例站一键载入、JSON 全量备份 | 全部 |
| 站场图编制 | Canvas2D 拖拽道岔/信号机/轨道区段，设备自动吸附股道中心线（y 坐标由所属股道决定），双击改名、滚轮缩放、Alt/中键平移、属性面板精编 | 信号设计员 |
| 进路表编制 | 按运行方向（上/下行）批量生成接车、发车、调车进路；逐条填始端按钮、终端按钮、道岔定/反位、防护道岔、区段占用顺序；支持手工新增与按拓扑重算 | 信号设计员 |
| 联锁冲突检测 | 同一区段、同方向被两条进路占用 → **敌对进路标红**并列出明细；防护道岔/道岔定反位要求冲突 → 单独橙色列出 | 全部（只读） |
| 仿真校验 | 按进路表逐条排列：按钮检查→选路→敌对检查→道岔转动→防护道岔→区段逐段点亮→信号开放；**失败明确指出卡在第几步及原因**；支持单步、批量回归、道岔/区段故障注入、锁闭状态监视 | 仿真测试员 |
| 审核发布 | 设计员提交即锁定；主管退回**必须写明问题条目**；发布后锁定并记录审核人、审核时间；支持解除锁定 | 设计员 / 主管审核员 |
| 统计汇总 | 各站进路条数、敌对进路对数、防护道岔冲突对数、仿真通过/未通过/未跑条目、通过率与规模对比图 | 全部 |
| 导出 | 单站进路清单 CSV（含始端/终端按钮、定反位、防护道岔、区段占用顺序、仿真结果，带 BOM 可直接用 Excel 打开） | 全部 |

## 核心建模

- `src/lib/topology.ts`：股道/道岔/渡线图拓扑。道岔为图节点、股道段与渡线为边；Dijkstra 按信号机授权方向做 x 单调路径搜索，自动产出道岔定反位要求（走渡线=反位）与区段占用顺序，防护道岔取路径相邻但不在路径上的道岔。
- `src/lib/conflict.ts`：敌对进路（同区段+同方向）与防护道岔位置冲突成对检测。
- `src/lib/simulator.ts`：排列进路步骤机，含设备缺失、故障封锁、他进路锁闭、敌对锁闭等失败分支与运行时锁闭表。
- `src/lib/generator.ts`：按方向/类型枚举信号机组合并经拓扑验证后批量生成。
- `src/store.ts`：响应式全局状态、工作流、CSV/JSON 导出、统计，localStorage 自动持久化。

## 快速开始

```bash
npm install
npm run dev        # 开发服务器 http://localhost:5173
npm run build      # 生产构建到 dist/
npm run preview    # 预览生产构建
```

打开后建议先点「载入示例站（甲站）」体验完整流程：站场已含 3 股道、4 副道岔（2 组渡线）、8 区段、8 架信号机，在进路表页选择方向与类型即可批量生成 18 条进路并查看敌对/道岔冲突，再到仿真页排列与注入故障。

## 测试

```bash
npm run test:unit   # 10 项核心算法测试（拓扑/路径/敌对检测/仿真失败定位/锁闭冲突）
npm run test:smoke  # happy-dom 真实挂载全部 6 个页面，覆盖导航、批量生成、工作流、导出
```

## 数据与权限说明

- 数据仅保存在当前浏览器 localStorage，清除浏览器数据会丢失，请定期用「导出全部数据备份（JSON）」归档。
- 角色切换决定操作权限：设计员只能在编制中/退回状态编辑；审核员负责退回与发布；测试员与审核员对站场和进路表只读，仿真功能三岗均可执行。
- 发布状态下存在敌对冲突的车站禁止发布；仿真未通过条目会在发布前二次确认。
