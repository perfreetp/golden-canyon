# 北岭雪场 · 雪道设计与运营审批

一个用 React + three.js 做的山地滑雪场雪道分级设计与造雪机布点审批系统。规划组在三维山体上画线、布设备，安全主管逐条审核，通过后才能生成压雪车作业单与巡逻排班。

```
npm install
npm run dev      # http://localhost:5173
npm run build
```

## 四个模块

**01 雪道设计** — 在三维山体上绘制雪道中心线（单击落点、双击成线），也可拖动已有控制点改线。选中雪道后实时给出：长度、落差、平均坡度、最大坡度、最小宽度、造雪覆盖率。线位校核按难度等级给提醒：

- 初级道任一段坡度 > 15° → 标黄「初级道坡度超限」
- 高级道出现上坡段 → 标黄「高级道出现反坡」
- 宽度 < 30 m → 标黄「会车宽度不足」

每条雪道带难度等级、开放季节、日均承载人数、下站。下方纵剖面显示高程线与坡度曲线，超限区段与造雪缺口分别加底色和红色斜纹。

**02 造雪布点** — 在地形上单击布设造雪炮（射程 58 m）或水枪（射程 40 m），也可按里程精确落点。每条雪道实时算覆盖率，射程覆盖不到的区段在三维雪道上和剖面条上以红色斜纹标出，并列出缺口里程与长度。

**03 安全审核** — 待审核队列逐条处理。核查清单按该雪道的等级与数据生成（初级道坡度、高级道反坡、会车宽度、造雪覆盖、交叉口/汇入冲突、下站承载）。有不通过项时「审核通过」禁用；退回必须填写整改意见，退回后雪道回到设计中并设计员可见意见。通过后可签发压雪车作业单与巡逻排班（含随单冲突提示）。

**04 运营看板** — 各雪道开放状态、造雪完成率、日均承载汇总；冲突与风险清单（平面交叉、汇入主道、下站排队）；事故记录；变更留痕（设计、造雪、审核、状态四类操作全部记账）。

## 冲突检查

- **平面交叉**：两条雪道中心线在平面上相交，按季节是否重叠、是否同时开放分级。
- **汇入主道**：一条雪道的下段落到另一条的线身上，视为汇入，提示缺少缓冲段。
- **下站排队**：同季共用同一索道下站的雪道合计日均承载超过闸机设计能力 8,600 人次/日时提示错峰。

## 地形与线位的关系

`src/lib/layout.js` 是唯一数据源：每条雪道是一条走廊折线加一个宽度剖面。地形模块沿走廊把山体削成平台（两侧留切填边坡），雪道分析再从这同一张高程场上读取坡度。所以：

- 改线位（拖控制点）→ 地形重新削坡 → 长度/坡度立刻跟着变；
- 报告中每一条数字都来自实际几何，不是单独存的属性；
- 雪道宽度剖面自带收窄段（T-04 的窄沟）时，地形平台也跟着收窄。

`src/lib/natural.js` 是滑雪场建成前的山体（落差剖面 + 山脊 + 沟槽 + 纹理）；`src/lib/terrain.js` 在上面削出平台并烘焙顶点色，`src/lib/scene3d.js` 负责三维渲染与拾取。

## 种子数据里的几个"有问题的"雪道

为了演示审核流程，初始数据里刻意留了几处缺陷：

| 雪道 | 状态 | 问题 |
|---|---|---|
| 云杉缓坡 T-01 | 已开放 | 上段坡度超 15°（初级道超限） |
| 松涛环线 T-04 | 设计中 | 窄沟段收窄至 26 m（会车宽度不足），造雪留缺口 |
| 雪兔练习道 T-05 | 待审核 | 各项校核通过，可直接演示"审核通过" |
| 北谷连接道 T-06 | 待审核 | 横切风积雪脊形成反坡（高级道反坡） |
| 鹰翼槽 T-07 | 封闭 | 与云杉缓坡、松涛环线平面交叉 |

## 目录

```
src/
  lib/layout.js      雪道走廊定义（唯一数据源）、宽度剖面、平台高程
  lib/natural.js     自然山体高程场
  lib/terrain.js     削坡后的地形场 + 三维网格（含烘焙光照）
  lib/trailMath.js   重采样、坡度/横坡分析、线位校核、冲突检测、作业单
  lib/scene3d.js     three.js 场景：地形、雪道带、斜纹缺口、设备、冲突标
  data/seed.js       初始雪道、造雪设备、事故、变更记录
  hooks/useSnowOps.js 状态与操作
  modules/           四个模块
  components/        三维视口、剖面条、侧栏、通用 UI
```

界面以桌面控制台为主，窄屏下纵向堆叠。
