# 消化内镜洗消间工艺布局图档加工系统

面向**院区基建科**与**内镜中心护士长**的工艺布局图档加工与归档平台。
技术栈：**Vue 3 + TypeScript + WebGL2 + Pinia + IndexedDB**，纯前端、零后端依赖，所有图纸、照片、版本均保存在本机浏览器数据库中。

## 业务能力对照

| 需求 | 实现 |
| --- | --- |
| 改造前图纸/现场照片建档编号，按院区/楼层/房间挂载 | 「院区楼层房间建档」三级树 + 「改造前照片/图纸」模块，编号规则 `院区码-楼层码-房间号-P-序号`，原图 Blob 与缩略图均存 IndexedDB |
| 分层平面图绘制清洗槽、消毒槽、干燥台、储镜柜、污物通道、洁污流线 | 编辑器 13 类工具，毫米级世界坐标；设备自带资产编号/型号/检修台账 |
| 单张图 2 万个图元 | 内置 20003 图元性能验证图；均匀网格空间索引 + 视口裁剪 + 颜色合批 |
| 缩放平移时视口外不渲染 | `SpatialGrid` 按 bbox 分桶，每帧只把与视口相交的候选图元送入 GL 管线（实测 2 万图元视口内仅画 8643 个，15 次 draw call） |
| 缩到低倍只显示房间轮廓和主干流线 | LOD0 阈值 `0.03 px/mm`，低于该缩放级别仅渲染 `lod0Visible` 图层（房间轮廓、墙体、洁污主干流线），HUD 实时提示当前层级 |
| 点选图元高亮并显示所属设备和最近检修日期 | 精确命中测试（旋转矩形多边形/折线距离），属性面板展示设备台账、最近检修日期、按周期计算的下次检修/超期提醒 |
| 图层单独开关 | 10 个业务图层独立显隐 + 透明度滑块，右侧图层面板实时生效 |
| 洁污流线交叉自动标红 | 折线线段求交引擎实时计算，交叉点画红色圆环警示，右侧横幅汇总数量 |
| 加工完与历史版本逐项比对并出说明报告 | 每次「提交新版本」生成只读快照；版本中心支持任意两版字段级 diff，一键导出可打印 HTML 说明报告（含签章栏、洁污核查结论） |
| 归档后按院区/楼层/房间号/改造年份检索 | 归档检索页五维组合查询（院区、楼层、房间号模糊、改造年份、关键字） |

## 快速开始

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # 类型检查 + 生产构建到 dist/
npm run smoke      # 无头浏览器冒烟测试（需本机安装 Chrome，见下）
```

首次启动自动写入演示数据：2 个院区、3 个房间、4 张图档（含一处洁污交叉的现状图、分流整改方案图、20003 图元性能图）、4 份改造前档案照片与初始版本快照。
演示数据通过 `SEED_VERSION` 管理，种子结构升级时自动清库重建；正式使用时删除 `src/App.vue` 中的种子初始化逻辑即可。

## 操作手册（编辑器）

- **缩放**：鼠标滚轮，以光标为锚点；**平移**：中键拖拽、按住空格拖拽、或选择「平移」工具
- **画设备**：左侧选择清洗槽/消毒槽等工具，在画布单击放置
- **画流线/墙/房间轮廓**：选工具后单击逐个加点，**双击或 Enter 完成**，Esc 取消
- **点选**：「选择」工具下点击图元；Delete 删除（锁定图元除外）
- **微调**：选中后方向键移动 100mm，Shift+方向键移动 500mm，R 键旋转 90°
- **图层**：右侧眼睛图标开关，滑块调透明度
- **版本**：「保存」只更新在制图档；「提交新版本」生成带变更说明的不可变快照
- **归档**：归档后进入检索库，可随时取消归档

## 架构

```
src/
├─ types.ts              领域模型（院区/楼层/房间/图纸/图元/照片/版本/差异）
├─ data/
│  ├─ idb.ts             IndexedDB 封装（响应式代理/Blob 序列化处理、整库重置）
│  ├─ factory.ts         图元/图纸/房间工厂与编号规则
│  ├─ geometry 外的 render/ 几何与索引
│  ├─ diff.ts            版本逐项比对（图元级 + 字段级 + 交叉点统计）
│  ├─ report.ts          可打印 HTML 说明报告生成
│  ├─ seed.ts            演示数据（含 2 万图元性能图）
│  └─ image.ts           照片缩略图/Blob 工具
├─ render/
│  ├─ renderer.ts        WebGL2 渲染器（LOD、裁剪、合批、交叉标记、命中）
│  ├─ camera.ts          世界(mm,Y 上)↔屏幕 相机
│  ├─ spatial-grid.ts    均匀网格空间索引
│  ├─ geometry.ts        bbox/线段求交/多边形命中
│  ├─ mesh.ts            粗线/箭头/圆/矩形三角化
│  └─ layers.ts          图层定义与配色
├─ stores/app.ts         Pinia 业务仓库（CRUD、版本、归档检索）
├─ components/           DrawingCanvas / LayerPanel / PropertyPanel / ModalDialog
└─ views/                建档树、照片档案、编辑器、版本中心、归档检索
```

### 渲染性能策略

1. **空间索引**：所有图元按 bbox 挂入均匀网格桶，视口查询 O(可见桶数)
2. **视口裁剪**：每帧只处理与视口矩形相交的图元，视口外完全不进入 GL 流程
3. **两级 LOD**：低倍缩放跳过全部设备/标注，仅保留房间轮廓与主干流线
4. **颜色合批**：同色图元合并到一个 mesh，全图通常十几次 draw call
5. **按需重绘**：脏标记驱动 RAF，无交互时不耗 GPU；文字标注走 2D overlay 不进 GL

实测（Chrome SwiftShader 软件渲染，1600×1000）：20003 图元，局部视口绘制 8643、裁剪 11360、15 次 draw call、约 51 FPS；独立显卡环境帧率更高。
